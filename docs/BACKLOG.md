# Backlog: findings to track after Milestone 5

This file lists problems and improvements found while reviewing the code, the design, and the security of RiskForge that are **not** fixed yet. Work on them after Milestone 5 (portfolio hardening), or earlier when the ticket named in the last column starts. A fixed finding keeps its row with Status `Done` and the change that fixed it; the review tables of `M3_NOTES.md`, `M4_NOTES.md`, and `M5_NOTES.md` describe the fixes. This file replaces `POST_M5_BACKLOG.md` (Milestone 3) and `POST_M5_BACKLOG_M4.md` (Milestone 4); ids are unchanged.

How to use it: one row is one trackable item. Change **Status** when work starts (`Open`, `In progress`, `Done: <commit or PR>`). Add new findings at the end of the right table with the next free id. Keep each row factual: what was observed, where, and what to do.

Severity: **High** can expose data or give a wrong decision in production. **Medium** weakens security or reliability under load or misuse. **Low** is maintainability, ergonomics, or a documented limit.

Origin: `Post-M5 review` is the read-only review of the whole code base after the merge of M5 (PR #10); it adds the **Features** table (prefix `FEAT-`) for product capabilities. `M3 review` is the Milestone 3 validation (RF-011 to RF-016). `M4 review` is the semantic and security review of the whole M4 diff (`main..feature/M4-governance`); `M4 validation` is found while running the tests and the live end-to-end flow (`scripts/e2e.sh`). Ids that start with `M4-` come from Milestone 4, the others from Milestone 3.
